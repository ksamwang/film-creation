# 场面调度（AIGC）

## 核心判断

剧本写"两人在厨房争吵"，生成模型拿到这句话只会给一张平均的厨房争吵图：人物居中、光线均匀、空间没有前后。场面调度要补的正是模型不提供的东西——这场戏占用空间的哪一块、人物在画面里的位置与朝向、机器从哪一侧看、这些镜头如何接成一个可读的空间。

AIGC 里没有临场试错，调度必须先变成文字资产：场景资产固定地理，人物资产固定身份，取景句与运动句（模式 B 为 SHOT / MOTION 块）固定观看方式。三者不写清，模型每次都会重新发明一个空间。

## 书里的原则

卡茨把调度对象分成场景、人物、摄影机，并让三者互为依据（《场面调度：影像的运动》第 1 章、第 3 章）。在 AIGC 里，这三者对应 S 场景资产、C 人物站位、取景与运动。书里的"动作的戏剧性范围"（1.3）决定机位在动作之内还是之外；"场景空间"（3.1）决定哪些地理必须写进提示；"问答模式"（《电影镜头设计》7.3）决定镜头顺序。本模块只写生成前的空间决定：一次生成一个镜头、同一场景参考图分角度重生成、用剪辑序列补覆盖。

## 先读哪篇

1. `01-space.md` — 先锁空间地理与纵深。
2. `02-blocking.md` — 再写人物位置、朝向与移动路径。
3. `03-camera-movement.md` — 给运动写起幅、触发与落幅。
4. `04-coverage.md` — 用问答模式排镜头序列。
5. `05-multi-character.md` — 三人以上的分层与特征污染。
6. `06-scene-analysis.md` — 把一场戏拆成 3–8 个镜头。

## 使用方式

每次只回答一个问题：这场戏的空间事件是什么？答案必须能落成位置、距离或朝向的变化，并能写成一句取景或运动描述。一个调度决定若不能在相邻两张生成图之间被验证，就不算决定。顺序固定：场景资产 → 站位 → 机位 → 运动 → 镜头序列。反过来做，每一层都在给前一层打补丁。

## 模块边界

本模块不管镜头美学、光色（见 visual），也不管表演微动作（见 performance）。它只管位置：人物在哪、机器在哪、观众先看到什么。风格层给形容词，本模块把形容词换成可生成的坐标。某种运镜的写法与可靠性查 `references/camera/lexicon-move.md`。
