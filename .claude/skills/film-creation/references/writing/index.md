# 写作查阅层：对白、叙事技巧、效果、诊断

## 这一层做什么

`craft/story/` 是**判断层**，回答「这个故事该往哪走」：不归点、beat、场景卡、视点。这一层是**查阅层**，回答三件事：

1. 某种对白手法或叙事技巧叫什么、怎么用、在生成里落到哪一镜、哪个资产。
2. 想让观众感到什么（悬念、爽、笑、哭），用什么机制。
3. 剧本哪里不对劲时，怎么确认是哪种病、怎么改。

一次只读一篇，不整层加载。

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `dialogue.md` | 对白手法：潜台词、攻防、人物声口、交代信息、节奏、钩子台词、修剪 | 写或改台词；用户说「台词太直白 / 太水 / 人物说话都一个样」 |
| `devices.md` | 叙事技巧：伏笔与回收、戏剧反讽、误导、倒计时、倒叙开场、闭环、镜像场景、反转、视觉母题、陪衬、开放式结尾等 | 结构需要一个技巧；用户点名某种技巧 |
| `intent.md` | 按效果反查：知识关系 → 悬念、惊奇、爽、笑、哭、恐惧等的机制、写法、镜头配合 | 用户只说想要什么感觉 |
| `doctor.md` | 剧本诊断：症状 → 怎么确认 → 原因 → 修法 → 落到哪个产物 | 用户给了一个剧本或 beat 表，问哪里不好、怎么改 |
| `sources.md` | 出处 | 需要核对出处时 |

## 和其他文件的关系

- 故事的骨架（不归点、beat、场景卡）仍以 `craft/story/` 为准；本层不重复，只链接。
- 竖屏短剧的台词规则（字数上限、语速估时、一镜一个说话人、VO / OS 的代价）以 `references/drama/04-script.md` 为准。本层每条手法附短剧写法；冲突时以 `drama/` 为准。
- 台词作为声音怎么处理（人声功能、旁白的知识关系、语音提示）见 `craft/sound/05-dialogue.md`。
- 台词背后的表演（目标、障碍、微动作）见 `craft/performance/02-action.md`。

## 对白的三条总规则

1. **台词是动作。** 每一句都在对对方做一件事：逼问、拒绝、讨好、试探、威胁、撤退。说不出这句在「做」什么，就删（《编剧的策略》5.1–5.2：对白推动情节，戏剧即冲突）。
2. **人物不说他们真正想说的。** 真正的意思藏在回避、转移、动作里（《21天搞定电影剧本》3.10 潜台词）。直接说出心里话，只留给全片最重要的那一句。
3. **台词会被模型直接说出来。** 每句都要能在所在的镜头里说完、口型落在对的脸上（`references/drama/04-script.md` §3）。写得再好、说不完的台词，在生成里等于不存在。
