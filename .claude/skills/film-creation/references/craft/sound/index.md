# 声音

## 这个模块解决什么

声音模块不回答“配什么音乐”，它回答四个决定：观众站在哪里听、画外有什么、什么时候把声音拿走、人声和音乐各自站在什么位置。四个决定做完，才轮到“好不好听”。

## 先读哪篇

先读 `01-perspective.md`。听点定了，画外、沉默、音乐、对白才有位置。其余四篇按当前问题读，不要一次全读。

## 子文件

| 文件 | 一句话 |
|---|---|
| `01-perspective.md` | 听点、视听场景、三种聆听模式：先定观众从哪儿听 |
| `02-offscreen.md` | 扩展域、相对与绝对画外、无形音角色：画外怎么造世界 |
| `03-silence.md` | 言语的中断、非情感共鸣、空无：沉默怎么撤层 |
| `04-music.md` | 情感共鸣与非情感共鸣、乐池与银幕：音乐的位置先于风格 |
| `05-dialogue.md` | 人声中心与词语中心、戏剧言语与文本言语：对白作为声音物体 |

## 共同前提

五篇共用《视听：幻觉的构建》的框架：声音不是画面的补充，它通过增值让观众以为意义来自画面；同步整合让声音和影像粘在一起；视听场景没有装声音的容器，只有声音之间的关系。所有规则都从这些前提出发。

## 怎么用

- 先定听点，再定画外；这两项写完，沉默、音乐、对白才有位置。
- 每个子文件的检查清单，在分镜前和混音前各跑一遍。
- 规则与风格层冲突时，以听点建立的空间为准，画面去补。

## 产出物

读完一个子文件，至少要产出一行可执行决定：听点句、画外地图、撤层表、音乐位置表、人声规则。没有产出，就等于没读。

## 模块边界

这一模块只管听觉判断，不教混音软件操作，也不替故事模块决定一场戏该不该存在。若一场戏在声音上找不到功能，先回到 `story/` 或 `staging/`，不要在混音阶段补戏。
