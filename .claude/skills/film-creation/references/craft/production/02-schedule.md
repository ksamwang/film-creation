# 生成顺序与镜头计划：用变化次数而不是剧情顺序排

## 核心判断

生成顺序不等于故事顺序。镜头计划的任务不是按剧本先后逐条生成，而是把共享同一角色状态、同一环境、同一光位的镜头压到一起，让"换"的次数最少。计划同时是承诺和工作稿：它约束批次，但必须给重生成留出余地。

## 书里的原则

**条形板（stripboard）是按条重排的工具。** 第十章说，软件出现前，人们把每场戏的信息写在硬纸细条上，靠挪动纸条排日程。AIGC 里每条细条就是一个镜头：shot ID、资产 ID、环境、光位、运动类型、依赖关系、尝试上限。

**先按故事时间录入，再以最经济合理的方式重排。** 书里重排看四组关系：场景、日夜、角色、特殊元素。翻译成生成顺序：同环境、同光位、同角色状态、同特效的镜头放一批；故事顺序只检查叙事，不决定先生成哪条。

**每天收工累计总页数，是负载表，不是成绩单。** AIGC 记录本批次的生成数、通过数、因脸、手、道具、运动失败数。累计的是可用镜头，不是生成条数。

**日程有两副面孔。** 第十章强调日程是路线图，但永远不能定死：书里用暴雨说明，变化必须提前二十四小时通知。AIGC 的"暴雨"是模型更新、队列延迟、连续失败；处理方式同样是改批次顺序或改拍法，不是改故事。

**定稿后只允许对白和词句修改。** 书里说，日程定稿后不能再动场景、道具、服装、灯光和发型化妆，否则分解、顺序和已排批次一起作废。AIGC 里这条变成版本冻结：资产 token 锁定后，只改台词、字幕、negative 和 motion 参数；一改角色或环境 token，整批已通过镜头全部重来。

## AIGC 执行

1. 先画依赖图：概念 → 资产 token → 关键帧 → 镜头首帧 → 视频 motion → 剪辑。上游没锁，下游不批量。
2. 每条 strip 写：shot ID、资产 ID、光位 token、运动类型、时长、依赖的上一镜、尝试上限、验收标准。
3. 排顺序分四步：先按环境聚，再按光位和时段分，再让同一角色状态连续，最后核对故事顺序。
4. 数三个"变化"：换角色状态次数、换环境次数、换光位次数。每多一次变化，多一次一致性 pass。
5. 先锁不可变项：角色 token、核心道具、主环境结构、交付时长。这些一变，全部批次重来。
6. 分开并行与串行：不同环境可以并行；同一角色的连续动作、同一镜头的首尾帧必须串行。
7. 每批次写失败原因，不只写通过率。失败集中在脸就改 token 与 negative；集中在运动就拆镜或降级。
8. 给最贵三镜和转场镜预留两到三成尝试额度，不平均分配；进入剪辑前冻结模型版本与 token 文本。

## 检查清单

- [ ] 每条 strip 有 shot ID、资产 ID、光位和依赖吗？
- [ ] 这一批镜头共享同一环境、光位和角色状态吗？
- [ ] 换角色状态、换环境、换光位各几次？
- [ ] 哪些镜头必须串行，哪些可以并行？
- [ ] 上游资产 token 锁定了吗？
- [ ] 最贵三镜和转场镜留了额外尝试额度吗？

## 常见错误

- 按剧本顺序逐镜生成 → 角色状态反复重载，漂移累积 → 先按共享资产分批。
- 把"同场景"当"同一批" → 光位和服装状态不同，仍要重做 → 按光位和角色状态再分一层。
- 只统计生成了多少条 → 可用镜头不够 → 统计通过条数与失败原因。
- 资产 token 没锁就批量生成 → 一处改动导致全批作废 → 先锁上游，再排下游。

## 与风格层接口

生成顺序决定覆盖策略。同环境、同光位、同角色状态连续，才有条件做长镜头和连续运动；一批跨三个环境，只能退回固定机位加必要插入。风格若要求大量运动，每条运动单独成条，并预留重试额度。条形板还能暴露哪些镜头可以合成连续镜头：同场景、同光位、角色不变的相邻镜头，是一次生成的首选；被拆批次的只能靠剪辑连接。
