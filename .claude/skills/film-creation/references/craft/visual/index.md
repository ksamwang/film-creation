# 视觉语言（AIGC）

## 这个模块解决什么

把剧本里的关系——谁有权力、谁在隐瞒、谁在看谁、这里是什么地方——翻译成能写进提示的画面变量。变量只有六组：景别与镜头关系、画幅内构图、焦距与景深、光、色、影像表面。六组不是清单，是一条决策链：先定观众必须知道什么，再选景别；景别定了，构图才有意义；构图定了，再选焦段；光决定暴露与隐藏；色与质感最后统一。顺序倒了，画面就会漂亮而空洞。AIGC 里每一步都要落成提示里的一句具体描述（模式 B 为一个 token 块）或一条失败模式，否则模型只会给你它的默认审美。

## 先读哪篇（按顺序）

1. `01-shot-grammar.md` — 景别、主镜头、平行剪辑、三角形原理。先保证一场戏看得懂、剪得顺。
2. `02-composition.md` — 位置、留白、角度、纵深。解决“画面里谁重谁轻”。
3. `03-lens.md` — 焦距、景深、变形镜头。把“站多远”变成透视后果。
4. `04-light.md` — 方向、硬度、光比、色温、画内动机。解决“看见什么、藏住什么”。
5. `05-color.md` — 基准色温、色板、饱和度。解决“这场戏属于哪个世界”。
6. `06-texture.md` — 介质、颗粒、反差、柔化、空气。解决“影像表面是否一致”。

只问一个镜头，先读 01、02；写整场视觉方案，按 01→06 走；写图像/视频提示，直接读各篇的“与风格层接口”。时间有限就先看 01 的三角形原理与 05 的色温，这两处最容易在生成里翻车。

## 三条使用原则

- 一个提示一个视觉主语；一场戏最多让两个变量“说话”，其余服从。
- 先锁资产（人物、场景、道具的参考图与描述），再谈构图与光色；否则每镜都换人。
- 每条规则要能变成提示里的一个可见单元或一条失败模式，并说清后果；不写“要有电影感”这类空话。

## 与其他模块

分镜、走位、覆盖读 `craft/staging/`；故事与场景读 `craft/story/`；导演/摄影风格读 `references/directors/` 与 `references/cinematographers/`。本模块只给画面判断，不堆导演名字。
