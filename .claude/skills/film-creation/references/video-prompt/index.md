# 视频提示词层：从分镜脚本到一次生成

## 这一层做什么

视频提示词是整条流程的最后一环：剧本（`writing/`）→ 分镜脚本（`storyboard/`）→ **提示词** → 生成。到这里，所有前面的决定都要变成模型读得懂、执行得出来的文字。

一条好的视频提示词不是一句画面描述，而是一份**压缩的制作文件**。它要同时替这些人说话：

| 角色 | 在提示词里负责 |
|---|---|
| 剪辑 | 几个镜头、每镜起止、怎么切 |
| 导演 | 这场戏在演什么、不是什么；表演；首帧；逐镜的动作节拍 |
| 摄影 | 每镜的焦段、机位、摄影机怎么动；光；画面质感 |
| 美术 / 造型 | 每张参考图负责什么；空间布局；道具在哪、不在哪 |
| 调色 | 色彩比例、反差、暗部 |
| 声音 | 画内声、台词、静默、要不要音乐 |
| 场记 | 人数、方向、道具状态、跨镜不变的东西；总锁 |

模型没有现场，它不会问「这里她该抱孩子吗」，只会按它见过最多的样子去演。**提示词的核心功夫是预判模型会怎么误读，然后提前封住。**

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `anatomy.md` | 提示词的段落：剪辑合同、全片硬约束、风格、戏的意图、人数锁、资产、空间地图、首帧、镜头锁、摄影机、光、色、空气与质感、逐镜时间线、物理、表演、声音、总锁、negative；每段写作用、写法、例、什么时候省；三档长度 | 写任何一条视频提示词之前 |
| `compile.md` | 编译：分镜脚本的每个字段落到提示词的哪一段、要补什么；切生成单位；预判误读；一条完整的多镜头提示词示例 | 手上有分镜脚本，要写提示词 |
| `sources.md` | 出处 | 需要核对出处时 |

## 三档长度

| 档位 | 用在 | 段落 | 长度（经验值） |
|---|---|---|---|
| **轻量** | 单镜、首帧生视频（画面已在首帧里）、简单空镜 | 动作、摄影机、声音，必要时加一句锁 | 约 60–200 词 |
| **标准** | 2–6 镜的对白或情节段落，参考图生视频 | 剪辑合同、硬约束、风格、意图、资产、空间、逐镜、声音、总锁 | 约 400–1500 词 |
| **重型** | 一镜到底、复杂调度、动作戏、人群、对一致性要求极高的段落 | `anatomy.md` 的全部段落 | 约 1500–3000 词 |

档位由**模型能力**和**镜头复杂度**一起决定：

- 文本编码器是大语言模型、支持多镜头和参考图的视频模型，读得懂长而有结构的提示词；CLIP 系模型 77 token 左右截断，只能用轻量写法（`references/aigc/prompt-syntax.md` §0）。
- 写长不是目的。每一段都要回答「不写这段，模型会在哪里错」；答不出来就删。
- 长度和效果的关系是社区经验，未经本包实测；换模型先用一条小样确认它读得进多长。

## 五条总规则

1. **先全局，再逐镜，最后再锁一次。** 剪辑结构、硬约束、风格、空间放在最前面，逐镜时间线在中间，关键不变量在结尾重复。模型对开头和结尾最敏感。
2. **每条约束都对应一个具体的误读。** 写「她不抱孩子」，是因为模型默认会抱。泛泛的「高质量、电影感」不对应任何误读，删掉。
3. **想要什么先正面写，顽固的默认再集中封住。** 正文写目标效果；模型很难改掉的默认（配乐、画面文字、多余的人、稳定器式顺滑、AI 质感）放进硬约束和总锁，把同义说法列全。
4. **情绪三件套：行为 + 理解 + 不是什么。** 「眉头松开、肩膀落下」（行为），「是松了一口气」（理解），「不是得意的笑」（不是什么）。只写行为，模型可能演错意思；只写情绪词，模型会演得夸张。
5. **全局段跨段逐字复用。** 同一场戏拆成几次生成时，风格、资产、空间、光、色这些段一字不改地复用，只换剪辑合同和逐镜时间线。改一个词，一致性就开始漂。
